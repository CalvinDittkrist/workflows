# 0018. A worker stage hands a fact to the next one through the worktree's git directory

Date: 2026-09-21
Status: accepted

## Context
The reviewer panel's verdict is produced in the worker's own context and needed in the pull request stage, which is a forked skill with a fresh context. The only channel was the skill argument, and the pipeline driver invoked the skill without one, so the author described the commits instead. On the run behind pull request #40 the panel ended `code=FIX security=PASS docs=PASS tests=FIX senior=FIX` at the round limit and the pull request said "No written panel summary was handed to this context"; the one page a maintainer reads before merging hid that the panel never passed. Relying on the agent to pass it by hand contradicts [ADR 0002](0002-scripts-do-agents-decide.md), and the architecture had no place for a fact that cannot be re-derived from git or GitHub: a verdict about a diff exists nowhere else.

## Decision
A worker stage may leave a fact for a later stage in `<this worktree's git directory>/worker/`, written and read by a worker script, never by an agent. `wf_state_dir` resolves it with `git rev-parse --git-dir`, not `--git-common-dir` as the standardisation run does: the common directory is shared by every worktree of a repository, and a worker's facts belong to one issue's worktree, so two workers in parallel would otherwise overwrite each other.

The first facts are the review's **round records** and the panel summary derived from them. The review stage records one round record per round it finishes: `panel.sh round` takes that round's `panel:` verdicts, `fixed:` counts and `disputed:` lines on stdin, refuses a block it cannot parse or one that states a chain, and stores it under the commit whose fixes it describes and whose gate run passed ([ADR 0019](0019-the-gate-runs-once-per-review-round.md)), numbered by the records already there. `panel.sh record` then takes only the `disputed:` lines that still stand and derives the summary from those records: the number of rounds, each reviewer's chain of verdicts (`FIX→FIX→PASS`), the `fixed:` counts summed by severity, and the draft verdict (draft as soon as a reviewer's last verdict is not `PASS`). Both calls describe the commit they are made at and refuse one that does not stand for the change: an unclean working tree, or a head the gate has not passed on. It refuses a summary without round records as well, stores it with the commit it describes, replaces any earlier record, and closes the rounds it derived. `panel.sh print` is the pull request stage's brief and is injected by its skill, next to the diff context. The skill argument stays as an override of the text; the draft decision always comes from the record, so no argument can turn a panel that did not pass into a ready pull request.

The round records are what makes the review stage resumable ([ADR 0032](0032-the-stage-measures-the-context-on-entry-and-a-handoff-grants-one-skip.md)). A stage that finds them continues at round N+1 and launches only the reviewers whose last verdict is FIX, and its brief quotes the rounds themselves, indented, for a context that did not run them. They count while the commit of the last one is still in the history of HEAD: once it is gone (amended, rebased) they describe other work, read as none, and the panel starts at round 1. The same call carries the round's own context checkpoint, because between rounds the stage's skill is loaded already and no injection can measure the context.

What may live there: a fact one stage of this pipeline run produces and a later one needs, small, plain text, owned by one script. Not a cache of anything git or GitHub already answers, and not state that a resumed session must have.

## Consequences
A review can be handed over after any round and continues where it stopped, at the cost of one script call per round: the rounds that ran are in the records, so a fresh context runs only the reviewers still on FIX and the round limit counts recorded rounds across contexts. Nobody writes the summary any more, so it can no longer state a panel that did not run, drop a round a context forgot, or drift from the verdicts the reviewers gave; what the worker reports at the end of the stage is the text the call printed back.

The pull request body carries the panel result verbatim, including a panel that ended on FIX and every `disputed:` line, and a panel that did not pass opens the pull request as a draft that only the maintainer lifts. The pipeline driver reports the same recorded text instead of quoting its memory. In yolo mode that draft ends the run: `finish.sh` refuses it and says so, because the point of the draft is that a person reads the body, and an autonomous run is exactly where nobody would. It does not trust the draft flag alone, which an agent step applies: it reads the record itself and merges only a panel recorded as ready, so a missed `--draft` cannot self-merge a branch whose panel ended on FIX.

The branch name is no longer the only state contract, so the loss of the directory has to be harmless: it is not versioned, not pushed and gone with the worktree. A stage that finds nothing reads `panel_summary: none recorded`, the verdict falls back to draft, and the pull request says the panel result is unknown rather than inventing one — a degraded run, not a broken one. A re-claim of the same issue starts a new worktree and therefore an empty directory, which is correct: the previous run's verdict said nothing about the new diff. Because the record names the commit it was taken at, a brief after further commits says how many they are, and the reader can see the summary does not describe them. Since the review stage became skippable — a `/worker:work` that resumes at the ci stage ([ADR 0029](0029-a-worker-resets-its-context-by-a-handoff-not-by-compaction.md)) never runs it — the one word `verdict` says `draft` for such a record as well: a script reads no `panel_head:` line, and an unattended finish must not merge on a summary that its own branch has outrun.
